# 评测数据集

36 个带标注的样本，对应架构 §16.2 的 **full regression** 层。这是唯一有参考答案的一层：

| 设施 | 有什么 | 缺什么 |
| --- | --- | --- |
| `scripts/benchmark.py`、`scripts/e2e_*.py` | 真实链路 + 结构化断言 | 没有参考答案，答得对不对看不出来 |
| `scripts/evaluate.py` | judge 打分 | 从 trace 抽样，没有标注可比，分数没有基线 |
| 这里 | 标准回答要点、正确页码、工作流程约束 | — |

## 三个维度，两个不用模型

| 维度 | 怎么判 | 用 judge |
| --- | --- | --- |
| 检索来源是否合理 | 实际引用页 vs 标注页码，算召回与精确 | 否 |
| 工作流程是否最优 | `must_call` / `must_not_call` / 调用次数上限 / 真实依赖顺序 | 否（另有一个 judge 单独打「路径绕不绕」的分） |
| 答案是否正确 | judge 逐条判参考要点覆盖了没有，以及有没有被禁止的说法 | 是 |

`--no-judge` 只跑确定性的那两个，不花模型额度，适合进常规检查。

## 怎么跑

教材切片先准备好（`scripts/e2e_fixture.py` 的 `SLICES`，五份，落在 `testdata/fixtures/`），
然后另起一套实例：

```bash
CP_PORT_OFFSET=3 STORAGE_DATA_DIR=testdata/eval ./scripts/dev.sh
```

```bash
.venv/bin/python scripts/eval_dataset.py --base http://127.0.0.1:8003
```

只看某一类：

```bash
.venv/bin/python scripts/eval_dataset.py --base http://127.0.0.1:8003 --only practice_grade,plan
```

脚本会自己建课、装教材、等索引，重复跑不会重复装。跳过的判据是文件名已经在课程里，
所以上一次跑到一半中断、教材停在 `uploaded` 没索引时，脚本不会补索引，那门课的检索会静默地全空。
遇到某门课整片零命中，先查 `GET /api/v2/courses/<id>/materials` 的 `index_status`。

## 教材 hash 是硬门

`dataset.yaml` 的 `materials` 记了每份切片的 sha256。教材内容一变，标注的页码就是错的，
这时候脚本**直接报错退出**，不会给出一个基于错页码的结论。切片是从固定 URL 下载 + 固定页范围
裁切，所以只要源没换版就能复现；真换了就得重新标页码。

这个段只记**样本标注依赖的**教材。`e2e_fixture.py` 的 `BIG_SLICES`（几十页的整章，
给 `scripts/e2e_library.py` 压知识页的节点上限用）没有样本引用它，所以不进这个段，
也不在 `SLICES` 里——评测会把同课程的切片全装进去，多一份几十页的教材会改掉检索基线。

## 标注约定

`must_include_pages` 只填「答案真的在这一页」的，拿不准的放 `acceptable_pages`（引了不罚也不加分）。
`forbidden_pages` 用于课程隔离样本 —— 引了别课的页即失败。

工作流程**不标注唯一正确的工具序列**。这个项目反复踩同一个坑：把模型的一种合法做法当成
唯一正确做法。所以只标四类能确定判定的约束：

- `must_call` —— 缺了就是没做该做的事（问答必须先检索，出题必须落 artifact）
- `must_not_call` —— 做了就是越界或白费（纯教材问答跑去联网、没让改计划却调 `plan_update`）
- `max_tool_calls` —— 绕远路的上限，留了 1-2 次余量，防的是原地打转而不是逼它走最短路
- `required_order` —— 只填真实依赖，比如批改前必须先 `artifact_read` 读到题目

`answer_points` 是可判定的命题，不是措辞要求。写「平均周转时间被拉长」，
不写「必须提到『护航效应』这个词」。

`notes` 记标注依据（为什么是这几页），用于复核。

### `global_synthesis` 这一类另有约定

这类问的是跨章节才答得出的全局问题：答案不在某几段原文里，要把一份教材里分散在多处的内容合起来看
（整体分成哪几部分、两种做法的取舍逻辑、一条线索是怎么推进的）。它的用途是给「知识页」改造留一个
可比的起点，所以题目按「向量检索天然答不好」来设计，不迁就当前版本能不能通过。

- `must_include_pages` 必须落在同一份教材里两个**互不相邻**的位置，这就是「全局」的判据；
  中间那些引了也对的页放 `acceptable_pages`
- 不出跨教材的题——那违反「不跨课程取证」这条产品边界
- 这类问题多查几次是合理的，`max_tool_calls` 统一留到 12；`web_search` 仍然禁，教材里有的东西不该联网查

## 加样本

按 `dataset.yaml` 里现有条目的形状加，`id` 用 `<category>-<序号>`。加完至少确认两件事：

1. 标注的页里真的有支撑答案的内容 —— 用检索接口查一遍，别凭印象
2. `must_not_call` 里的工具确实不该出现 —— 想清楚有没有一种合法路径会用到它

`plan` 类样本要额外核对 `service.py` 的 `_PLAN_INTENT` 正则：「该放行」的问法必须真的命中它，
「该拒」的必须真的避开。这条最容易标错。

### 观察到的（依据）

- synth-006 两遍都没引到 p.12。教材把这条性质命名为 closure property 并说明为什么重要，只写在
  p.12 的 6.6 节开头；两遍实际引到的是 {5,6,7} 和 {5,8,9,10}。
- synth-001 两遍都没引到 p.10，两遍都引到了 p.9。只跑本类那遍的回答据此写成「章末还剩假设 4 和
  假设 5 两条没解决」——p.9 末尾那句 “we still have two assumptions which need to be relaxed”
  是 7.7 节的过渡句，7.8 节在 p.9–p.10 已经处理掉了假设 4。
- 同一条 synth-006，只跑本类那遍 judge 把四条要点全判成覆盖，全量那遍只判过两条。那次回答的正文里
  写的是「若干个独立高斯的相加……需要我再确认教材是否展开」，而这条就在 p.8。
- 两条操作系统样本在两遍里都引了 p.13（课后习题页），它不在标注的 acceptable 里。
- 流程 judge 对同样「只调用一次 `search_materials`」的 synth-003 与 synth-004 给了 1 分和 4 分，
  给 synth-003 的理由是「查询被中断，无法完成实际回答」，而那一条召回 1.00、四条要点全覆盖。
- 工具序列几乎全是重复的 `search_materials`：两遍加起来只出现过两次 `list_materials`，没有别的工具。

### 判断（推断）

- 检索召回是这一类目前唯一稳定的区分维度：0.833 对 0.967，缺的都是「离题面最远的那个位置」。
  看上去检索按整句问句取最相似的那一簇分片，第二个位置要靠模型自己想到换检索词才补得上，
  而它在这几条里没有系统地这么做。
- 答案要点这一维接近饱和（22/24、23/24），大概率是因为五份切片都取自公开教材，模型的内参知识能把
  没召回到的部分补上，而 judge 只看语义覆盖、看不出这句有没有教材支撑。拿它单独当「知识页有没有用」
  的判据不可靠，对比时要和召回、实际引用页一起看。
- 流程 judge 只拿到工具名的序列，看不到每次的查询词和返回，于是把「换个词再查一次」判成原地打转。
  这一类问题本来就该多查几次，这个维度对它有系统性偏见，分数当噪声看。

### 已知边界

- 五份切片都只有 9–13 页，一次混合检索返回的分片就可能横跨整份文档——synth-003、synth-004 一次调用
  就把两端都引到了。切片越小，这一类样本能施加的检索压力越弱；教材换成完整章节或整本书时召回会更低。
- 检索精确（0.831）在这一类上不是个干净的信号，别拿它当收益判据。全局问题的合法引用面本来就宽，
  标注只把真正支撑答案的页放进 must/acceptable，而像 os-cpu-scheduling.pdf p.13 的课后习题讲的
  就是同样那几个指标，引了会扣分。这个数只有在 must/acceptable 不变的前提下才可比。
- 硬约束这一层对这类样本不起区分作用（6 条全过）。`must_call` 只要求 `search_materials`，
  `max_tool_calls` 留到 12 而实测最多用了 6。往后对比就看召回、引用页和要点覆盖。
