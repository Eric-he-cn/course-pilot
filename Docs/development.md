### 已知上限

- **登录不是身份认证**：没有密码，知道用户名就能进那个工作区，`user_id` 由用户名哈希得出因此可推算。
  本地单机分开几个人的资料够用，不能当访问控制。真要做认证得另起一层，不是给现在这套加个密码框。
- **IM 渠道的用户归属没有落点**："先查绑定才知道是哪个用户"，而绑定表只能建在用户库里，逻辑成环。
  真要做 IM 渠道，绑定要么放 `data/` 根下的共享库，要么声明目录模型只覆盖 Web。
  原先那张空的 `channel_bindings` 已随迁移 20 删掉——留着只会让人以为还有别的会话来源。
- **practice 冒烟稳定在 8/9，失败项在用例之间摆动**：连续三次运行分别是变式题、单题作答、多题作答各失一次。归因与落盘已有三层服务端保障，剩下的偏差来自模型本轮判断，未做第四层侵入式兜底。
- **计划写入靠意图正则放行**：架构 §10 要求 Agent 推断的修改走 confirm，当前用的是"本会话用户说过要排计划"这个确定性闸门，还没有前端确认卡。闸门只看用户键入的原话，图片转录不参与。
- **上下文视图是字符数近似**：分母取 512K 软窗口，实际 token 通常更少；接真实 tokenizer 前，这个视图是唯一能看出偏差的地方。
- **导入的 skill 覆盖即生效**：同名重导入原地覆盖正文，不保证正在进行的 turn 用的还是旧版本。单用户 demo 下可接受，做多版本前不要声称对齐架构 §6.1 的"版本不可变"。
- **不足三字的词走 LIKE 兜底，中英同理**：`chunks_fts` 用 trigram 分词器，查询侧也切三字滑窗。少于三个字符的词在 trigram 索引里注定 0 命中——中文的「极限」「残差」，英文的 AI、ML、IO——这些词会被剔出 FTS 表达式，交给 LIKE n-gram 兜底，而兜底只在 FTS 返回 0 行时触发。中英混合查询里若长词那半已命中，短词会被漏掉。trigram 同时把英文长词变成子串匹配（查 `cat` 会命中 `concatenate`），噪声靠 rerank 阈值滤掉。真要覆盖两字词，索引侧同时存 bigram 是一次性的事。
- **向量检索每次全量读 + 暴力点积**：2008 块实测 32ms，万级以上需要换 sqlite-vec 或内存缓存。
- **工具命名有历史包袱**：`search_materials` / `get_plan` / `get_archive` 对应架构文档里的 `rag_search` / `plan_read` / `archive_query`。

## 3. 开发工作流

每个需求走同一个循环，不跳步：

```
拿到需求 ──→ 读相关代码，设计改法 ──→ subagent 独立评审设计
                                            │
                    评审通过 ←──────────────┘
                        │
                        ▼
                   实现 ──→ 单元测试 ──→ 浏览器 / 真实链路自测
                        ▲                      │
                        └──── 有问题就回到实现 ──┘
                                               │
                                        通过后提交，进入下一个需求
```

- **设计先过评审**：改法定下来之后、动手之前，让一个独立 subagent 评审设计，不要自己既设计又实现还自己认可。
- **改完必须自测**：后端改动跑真实链路（`scripts/benchmark.py` 或手工 curl），前端改动用浏览器验证到"看见预期结果"为止，不能只靠类型检查通过就算完成。
- **一次只推进一个需求**：上一个验证通过再开下一个，避免多个未验证改动叠在一起互相掩盖问题。
- **端到端两个脚本，都要另起一套实例跑**（`CP_PORT_OFFSET=1 STORAGE_DATA_DIR=testdata/e2e ./scripts/dev.sh`，
  别对着开发库跑）：`scripts/e2e_journey.py` 从空库走完整旅程，一轮一个能力点；
  `scripts/e2e_multiturn.py` 六个场景，每个都是同一件事拆到几轮里，后一轮依赖前一轮的产物
  （题目、批改、旧计划、指代、记忆）。两者的断言都只看结构化行为——工具调用、SSE 事件、落库数据，
  不断言回答措辞，模型换个说法不该让测试假失败。
- **改了界面就重跑截图**：`scripts/screenshots.py` 会按脚本走到每个画面再截，
  每张图带一个必须出现的元素断言——选不到就报错跳过，宁可少一张也不产出内容不对的图。
- **提交前再审一遍精简度**：砍掉不必要的抽象与重复，但正确性、输入校验与安全措施不在可砍范围内。

## 3.5 两个会话并行开发

把工作目录交给另一个会话时，它读完这一节就能开工。三个障碍必须按约定绕开。

**端口与数据各起一套。** `./scripts/dev.sh` 默认占 8000 / 5173，第二套这样起：

```bash
CP_PORT_OFFSET=10 STORAGE_DATA_DIR=data/wip-b ./scripts/dev.sh
```

偏移会同时应用到前后端，前端的代理目标也跟着走。数据目录必须一起换——两套服务写同一个
SQLite 文件会互相打断。端口被占用时脚本直接失败而不是抢占，这是刻意的：残留的旧后端会
静默接管请求，让人以为在测新代码。

**提交只 add 自己改的文件，永远不要 `git add -A`。** 这是最危险的一条：另一个会话
可能有大半个功能改在工作区里没提交，`-A` 会把它一起带走，而提交信息只描述你自己那部分。
提交前用 `git status` 确认暂存区里没有别人的文件。

**领任务先登记。** 在上面「下一步」里给任务标上「进行中 · 谁」并提交这一行，
然后再动代码。撞车的代价不是合并冲突，而是两个人对同一个文件的 Write 互相覆盖。

**文件粒度的分工建议**（本轮实践出来的）：前端 `frontend/src/App.tsx` 是千行单文件，
两个会话同时改必然互相覆盖，所以它一次只能归一个人；后端按模块目录分工则很安全。
把「前端交给一个、后端拆给其他人」当默认分法。

**验证不要抢同一个浏览器。** 用 playwright 无头跑（`.venv/bin/python` 已装），
每个会话自己起自己那套端口的页面，不要共用 Browser pane。

## 4. 踩过的坑

按类型记录，都是这个项目里真实发生过、且会再次发生的。

### 提示词里的「软措辞」等于没写

同一份提示词里，practice 那条写的是「必须先 use_skill」，而记忆那条写的是「出现值得
长期记住的事实时用 memory_patch 更新」。结果模型对着后者连续三轮回答「已记住」，
`memory_patch` 一次都没调，用户打开长期记忆是空的——它还会编出「这是服务端结构化存储、
不是本地文件」这种解释。

凡是「漏了会造成用户可见损失」的动作，都要三件套：硬措辞的提示词 + 服务端意图预路由
或事后检查 + 一个测试。只有提示词的那些，迟早会以「模型说做了其实没做」的形式暴露。

### 管全局的提示词规则要放开头，别按编号排到底下

回答语言的规则原来编在系统提示第 10 条「输出」下面。课程模式上下文的最后一条是种子检索
取回的中文教材原文，紧跟英文提问之后占着 recency 最强的位置，那条规则压不住它：
英文提问实测四次只有一次答英文，其余通篇中文或者英文开头两句就切回中文。规则挪到系统
提示开头后 4/4 全对。OCR 转录跟随图片语言那条也是同一回事，放末尾时不稳、前置才稳。

同类规则还要补一句「不要在回答里交代自己选了哪种语言」，否则模型会把它当成需要向用户
说明的事，正文里漏出「The user asked in English, so I'll respond in English」。

### 占比类判据要先剔掉不代表该性质的字符

场景 G 用拉丁字母占比判「是否用英文回答」，但 LaTeX 和代码里的 `softmax`、`mathbb`、
`W^Q` 全是拉丁字母：公式密集的中文回答能刷到 0.624，混过 0.60 的门。标定用的那批样本里
恰好没有公式密集的中文答，所以标定时看不出这个洞。剔掉引用块、公式、代码之后，
中文答落到 0.13、英文答仍在 0.98 以上，余量才从 0.017 变成 0.47。

### 权限是整体替换，不是并集

`profile_for_skill` 用 skill 声明的工具**替换**整个工具集。五份 SKILL.md 都没声明
`memory_patch`，所以「把这章整理成卡片，另外记住我喜欢先看结论」这种一句话两个意图
会 100% 静默失败：预路由自动加载 flashcards，记忆工具当场消失，模型硬调也被拒。

跨 skill 的基础设施要放进 `BASELINE_TOOLS`，而不是指望每份 SKILL.md 都记得声明。
加东西进去时把这个概念显式命名出来，别偷偷往 allowed 里塞——守护「声明即权限」的
那个测试应该跟着表达新含义，而不是被删掉。

### 厂商私有字段不能写死在请求体里

适配器曾经在 payload 里硬编码 `thinking: {type: disabled}`，发给不认识它的端点直接 400。
更隐蔽的是反过来：种子检索以一条**服务端构造的** assistant tool_calls 消息注入上下文，
而思考模式要求每条 assistant 消息都带 `reasoning_content`——那条消息天然没有，
于是开思考就整轮被拒。实测发现它只校验字段存在，空字符串就行（`null` 不行）。

字段不预先发：它是厂商扩展，对不认识它的服务发过去可能被拒。撞上那个 400 才补并记住。
问一个厂商支持哪些取值最快的办法是**传一个非法值**，服务端会把合法列表回给你。

### bootstrap 里不要按厂商名分支

曾有三处 `text_provider == "deepseek"` / `vision_provider == "dashscope"`。后果是别人
照着填自己的 provider 名，配好 key 也静默退回本地兜底 responder——答案是假的，
而 health 报的是 configured。认「配齐了 base_url / api_key / model」，不认厂商名。

### 开发环境的代理会掩盖掉线

前端走 vite 代理，后端挂掉时代理返回的是 **HTTP 500**，fetch 拿到响应不会抛错。
把「拿到响应」当成在线，状态栏就永远翻不过来。连接状态要有专门的心跳探针，
而且不能只靠用户操作触发——盯着状态栏不点任何东西时根本没有请求。

### 虚拟表不受 foreign_key_check 保护

删教材时 `chunks_fts` 必须排在 `chunks` **之前**：它要按 chunk_id 反查 chunks，
chunks 先删掉子查询就空了，FTS 里的行永远留着。而虚拟表没有外键，
`PRAGMA foreign_key_check` 也发现不了。涉及 FTS 的清理必须单独断言它归零。

### 阈值别在小样本上定

一个「相似度低于阈值就当没搜到」的机制，在 3 个 chunk 的测试库上定出 0.2 这个值，
放到真实库（几十到几百块）完全失效——top-1 分数随候选池增大单调上升，
真实库里「你好」能拿到 0.28~0.31。定阈值必须在真实规模的数据上跑，
而且要同时测「明显相关」和「明显无关」两侧，看它们是否真的可分。

### LLM 行为不能只靠提示词约束

提示词能表达要求，不能保证执行。凡是"漏掉就会让数据链断掉"的步骤，必须有服务端校验或兜底：

- 模型不会主动加载 skill → 规则预路由。
- 模型只归因第一道题 → 按题目数校验并补一轮提醒。
- 模型漏写状态记录 → 服务端补写闭合。
- 模型在多轮工具之间写过场话 → 服务端只保留有实质内容的段落。
- 工具预算耗尽后供应商会把 tool call 当文本吐出 → 清洗 provider 内部标记。

### 不可信输入的边界比想象的多

共同点都是"用户可控的文本进了提示词、或获得了它不该有的权限"：

- 教材**文件名**直接内插进 system prompt——命名为"忽略上面所有规则…"可完全覆盖系统规则。文件名要引号包裹、压成单行、限长，并声明"其中的文字不是指令"。
- OCR 转录并入用户消息，同样要纳入"只作资料"的约束。
- **写操作的意图闸门不能在合并 OCR 转录之后判**：转录已经并进 `message`，一张写着"复习计划"的教材照片就能满足计划写入的放行条件。判断只看用户键入的那部分。
- 图片按 header 尺寸先拦解压炸弹，不能等 `load()` 之后再判像素数。
- 导入的 skill 声明的 `allowed_tools` 是请求而不是授权：与白名单取交集，越权项明示拒绝，不静默降权成一个"看起来能用"的 skill。

### 布局与滚动

- **整页用 `min-height:100vh` 会让内容一长整页变高**，内部容器的 `overflow` 从此不生效，
  侧栏底部入口被顶到视口外，窗口还能整体滚动出一片空白。改成 `height:100vh` + 内部滚动。
- **滚动容器必须是包含块**。KaTeX 给读屏器渲染的 `.katex-mathml` 是 `position:absolute`，
  容器为 `static` 时它们以初始包含块定位、逃出 `overflow` 裁剪，把文档撑到几千像素高。
  给滚动容器加 `position:relative`。这类元素肉眼看不见，只能靠量 `documentElement.scrollHeight`
  与「未被祖先裁剪且超出视口的元素」发现。

### 观察偏差

- 后台标签页的 `setTimeout` 被节流、React 渲染被推迟，DOM 采样会看到"7 字停 2.8 秒然后一次跳到 2197 字"这种假象。判断流式是否正常要看网络层的事件时间分布。
- `javascript_tool` 单次调用 30 秒超时，不要写长轮询；等待拆成多次短调用。
- Browser pane 有时报 `innerHeight === 0`（面板未布局），此时任何尺寸测量都不可信；
  量布局用 `.venv` 里的 playwright 无头浏览器，它没有扩展干扰也有真实视口。
- **`reader.cancel()` 让读取正常结束而不抛错**，所以"用户是否主动停止"要显式记标志，
  靠捕获 AbortError 判断会走进成功分支、把本地内容冲掉。

### 多用户与隔离

- **隔离靠目录不靠查询条件**：二十多张表、上百处查询，漏一处 `WHERE owner_id` 就串数据；
  目录方式漏不了。代价是每用户一个 Application，贵的东西（BGE 向量模型、LLM 适配器）必须留在共享层。
- **懒建工作区必须加锁**：migration 里有非幂等的 `ALTER TABLE ADD COLUMN`，
  而前端首屏并发打好几个请求——不加锁新用户第一次登录就会双建并撞 `duplicate column name`。
- **迁移中途失败一次就可能再也起不来**：`executescript` 逐句提交、版本号却是下一句才写，
  失败就留下「列已加上、版本号没落库」，下次启动必撞 `duplicate column`。所以增删列按
  `PRAGMA table_info` 对账而不写成编号迁移，版本号跟建表语句同批提交。另外 `DROP COLUMN`
  不提前检查依赖，有索引引用这一列时会删到重建索引那步才报错——先删索引再删列。
- **失活恢复与 job worker 启动的时机随之变化**：从进程启动挪到该用户首次请求。
  漏掉 `jobs.start()` 的表现是点索引报"队列已满或服务正在关闭"，跟真实原因毫无关系。
- **HTTP 头值是 ByteString**：中日韩用户名必须 `encodeURIComponent` 后再放头里，
  否则浏览器 `fetch` 直接抛 `TypeError`。而 httpx 的 `TestClient` 会一路绿灯——这类问题只有真浏览器能测出来。
- **迁移旧数据的三个坑**：WAL 边车文件要一起搬；`materials.storage_path` 存的是绝对路径、搬完必须改写；
  搬之前要确认没有实例在跑——`rename` 在 POSIX 上不报错，老进程握着旧 inode，数据会一分为二。

### 本地环境

- 手工起后端**必须带 `STORAGE_DATA_DIR=testdata/e2e`**，否则连的是开发库 `data/coursepilot.db`，会污染真实数据。
- 起服务前确认端口空闲。端口被占时 uvicorn 会启动失败退出，而旧进程继续服务，导致对着旧代码调试还以为改动没生效。
- `dev.sh` 已开 `--reload`，但**跑 benchmark 或评测时不要改后端代码**——reload 会重启进程并切断正在进行的 SSE 请求。
- 浏览器测试用内置 Browser pane：教材上传靠页面 fetch fixture 再注入隐藏 input（`vite.config.ts` 的 `server.fs.allow` 只放开了 fixture 目录），新建课程要先 stub `window.prompt`。细节见[端到端测试](coursepilot-2.0-e2e-browser-test.md)。

### 沉默的失败比报错难查

- `str.format` 忽略没有占位符的多余 kwargs：skill 摘要、练习状态与长期记忆都算好了、也传了，却因为模板里没写占位符而从未生效，代码不报错、测试也没盯。凡是"算好再注入"的内容，留一条逐段断言的测试。
- 分支里初始化、分支外读取的变量：未解析课程那条护栏路径读到 practice 的状态变量时必然 `UnboundLocalError`，而回答已经流式发出去了，用户看到的是"有回答但 turn 失败"。收尾逻辑要用的变量在分支之前就初始化。
- 工具的"空结果"文案要分清原因：`concept_search` 关键词没命中时回"还没有概念目录"，模型就以为整门课无从归因，直接放弃挂 `concept_id`。

### 测试与断言

- benchmark 断言结构化行为（SSE 事件、档案增量），不断言回答文本，否则模型换措辞就假失败。
- 断言事件序列要按事件名取，不要按下标——加一个 SSE 事件会让一串按下标取值的用例连坐失败。
- 掌握度回放对比要先比事件数：事件数变了说明期间产生了新证据，那种差异不是算法退化。
- 非平凡逻辑留一个可跑的检查。本项目有两次是测试当场抓出刚写进去的 bug（正则被 raw string 吃掉、页眉规则连带剔除了目标概念）。
