# CoursePilot 2.0 前端设计

本文补充 [产品设计](coursepilot-2.0.md) 与 [架构设计](coursepilot-2.0-architecture.md) 中的前端部分，作为 React SPA 的实现基线。目标不是做一个功能堆叠的管理后台，而是做一个安静、清晰、愿意长时间停留的个人学习空间。

## 1. 视觉方向与设计原则

视觉识别方案代号 **Terminal**，落地于 `frontend/src/styles.css`。总体原则：

- 避免大面积渐变、霓虹和“AI 紫”；分区靠细边框，不靠浮起卡片。
- 内容优先。聊天、教材原文、公式和计划占据视觉中心，导航与工具在需要时出现。
- AI 行为可见但不过度打扰：检索、调用 skill、更新档案以简短状态或回执呈现，不展示原始思维链。
- 重要状态同时使用文字、图标和颜色表达；掌握度不只显示一个看似精确的百分比。
- 不制作高成本品牌插画。空态使用排版、细线图标和一张简洁内容卡即可。
- 同一课程使用稳定的小色标辅助识别，但所有课程仍共享统一主色与组件体系。

### 1.1 概念

**开发者工具的浅色模式**（Linear / Vercel / Raycast 一系）：纯白画布、锐利细边框、等宽字体承担元数据、把「系统正在做什么」当作设计语言的一部分。这与产品强调证据、引用、trace、可审计的理念一致——界面本身就应该透明、精确、可信。

国际化、极简、极客；明确反对：AI 通用风（渐变、AI 紫、大圆角胶囊、弥散阴影）、中文字 logo、彩色装饰。

### 1.2 识别元素

1. **`>_` 方块 logo**：黑底白字等宽 `>_` + CoursePilot 字标 + `v2.0` 版本 tag。
2. **`❯` 提示符**：Agent 回答头部（`❯ CoursePilot`）与输入框前缀，唯一的「角色」符号。
3. **等宽元数据层**：分区标签（WORKSPACE / NAV / SESSIONS）、导航编号（01–04）、时间、页码、分数、状态一律等宽字体；正文与控件保持无衬线。
4. **代码式引用**：教材引用渲染为 `[1] d2l-en.pdf:409`（file:line 格式），收在带 `SOURCES · n` 标签的引用面板里。
5. **底部状态栏**：常驻一条 26px 等宽状态栏，展示真实的连接状态、provider/model、检索 backend——不是装饰，读的是 health 接口。
6. **戳记状态**：状态标签为等宽小字 + 1px 描边，无填充底色。

### 1.3 设计 token

```css
--bg:     #FFFFFF   /* 画布：纯白 */
--panel:  #FAFAFA   /* 面板：侧栏、气泡、代码块 */
--text:   #18181B
--muted:  #71717A
--border: #E4E4E7   /* 1px 锐利边框，分区只靠它 */
--accent: #059669   /* 终端绿：只用于 icon、提示符、激活态、状态点 */
--danger: #DC2626
--warning:#B45309
```

- 圆角 6–8px；表意性圆形控件（开关、色点）除外。
- 阴影只允许 `0 1px 2px rgba(0,0,0,.04)` 级别的贴地投影。
- 主题色不做大面积填充；仅索引流水线「进行中」步骤允许 accent 实底。
- 课程色由服务端下发，仅用于小色点。

### 1.4 字体

```css
--sans: -apple-system,BlinkMacSystemFont,"Helvetica Neue","PingFang SC","Noto Sans SC",sans-serif
--mono: ui-monospace,"SF Mono",SFMono-Regular,Menlo,Consolas,monospace
```

| 用途 | 字族 | 规格 |
| --- | --- | --- |
| 页面标题 / hero | sans | 24px，字重 650，字距 -0.02em |
| 正文（含 Agent 回答） | sans | 14–14.5px / 行高 1.75 |
| 分区标签、编号、引用、状态栏、时间与分数 | mono | 10–12px，标签字距 .1em |
| 卡片标题 | sans | 15px，字重 600 |

只用系统字体栈，不引入 webfont。

### 1.5 组件规范

- **按钮**：主按钮墨底白字 6px 圆角；次级按钮白底 1px 边框；破坏性操作红字。
- **输入区（composer）**：1px 边框 + 贴地投影，左侧 `❯` 绿色提示符；聚焦时边框变 accent。
- **选中态**：白底 + 1px 边框 + 贴地投影（浮出面板），不用填充色表达选中。
- **引用面板**：回答末尾的浅灰面板，`SOURCES · n` mono 标签 + 代码式引用链；点击打开右侧引用抽屉。
- **索引流水线**：mono 戳记步骤，已完成=墨字，进行中=accent 实底白字，未开始=灰字；进度条 4px accent。
- **空态**：`❯` 符号 + 标题 + 一句说明，不用插画。

### 1.6 动效

- 只保留必要过渡：侧栏收合、开关滑块、边框颜色，一律 ≤ 180ms。
- 不做入场动画、骨架屏闪烁和渐变流光。`prefers-reduced-motion` 下全部关闭。

### 1.7 禁止清单

- 渐变、玻璃拟态、弥散阴影、大圆角胶囊。
- 中文字或表意字符作为 logo / 图标。
- 彩色填充的状态标签与 chip。
- 装饰性 emoji / 插画作为界面元素。
- 状态栏展示假数据；所有系统信息必须来自真实接口。

## 2. 信息架构

```text
全局框架
├─ 学习
│  ├─ 对话 /chat/:sessionId
│  ├─ 知识仓库 /knowledge（内部选择课程；RAG / Wiki 双 tab）
│  ├─ 计划 /courses/:courseId/plan
│  └─ 学习档案 /courses/:courseId/archive
└─ 管理
   ├─ 课程与教材 /settings/courses
   ├─ Skills /settings/skills
   ├─ IM 渠道 /settings/channels/im
   ├─ 模型与能力 /settings/models
   └─ 运行记录 /settings/traces
```

桌面端左侧顶部是工作区切换器：第一项固定为默认“通用模式”，其后列出带稳定颜色的课程。切换只改变当前浏览工作区，并新建或续接相应 scope 的会话，不修改旧会话。其下始终展示完整会话列表与新建按钮；每条会话用课程色点表达归属，通用会话另保留通用图标，尚未解析课程时使用中性灰。

课程会话顶部显示“绑定课程”；通用会话顶部显示“通用会话 · 本轮解析到：课程名/尚未确定”。`last_resolved_course_id` 只用于列表色点，不能在前端被解释成永久绑定。

设置入口与学习主导航分开，trace、模型能力等开发者信息不进入日常学习界面。

## 3. 响应式布局

### 3.1 桌面端

- `≥ 1280px`：左侧栏 248px；主内容自适应；对话正文最大宽度 820px；可选右侧上下文抽屉 320px。
- `960–1279px`：左侧栏 216px；右侧信息改为覆盖式抽屉。
- 页面顶部 56px，内容区内边距 24–32px。Wiki 和档案可使用 1120px 宽内容区，聊天不随屏幕无限变宽。
- 左侧栏可折叠为 72px 图标栏，折叠状态持久化在本地。

### 3.2 移动端

- `< 960px`：顶部显示当前 scope 与页面标题；底部四项导航为“对话 / 知识仓库 / 计划 / 更多”。
- 会话历史、目录、筛选器与引用详情均使用全高抽屉；不把桌面三栏强行压成小三栏。
- 对话输入区吸附底部并适配安全区域；键盘弹出时保持最新消息与输入框可见。
- 计划默认使用日程列表，日历是次级视图；表格转换为卡片或横向可滚动区域。

## 4. 核心页面

### 4.1 对话主界面

桌面结构为“会话侧栏 + 对话正文 + 可选上下文抽屉”。

**顶部栏**

- 当前 scope、解析/绑定课程色标和连接状态始终可见。通用会话必须区分“本轮解析课程”与“固定课程”。
- “知识仓库”状态只显示当前解析课程是否有可检索材料；Wiki 开关不抢占聊天主界面。
- 右侧提供“课程资料”“本轮引用”“更多”，不放全局模型参数。

**消息流**

- 用户消息使用浅色实心气泡；Agent 回复采用无气泡正文，提升长文、公式和引用的阅读体验。
- 教材引用显示为文末编号和可点击引用 chip；点击后在右侧抽屉打开文档名、页码与原文片段。
- 工具过程合并成一行可展开的“已检索 3 处教材内容”“已更新计划”，默认不铺开日志。
- `practice` 的题目、作答与讲评沿用普通 Markdown 消息；服务端若返回公开的通用 artifact，前端只按 `kind` 做轻量容器展示，不假设固定的题目、答案或评分 schema。`visibility=model_private` 的 payload（包括 answer key/rubric）永不进入前端。
- 图片输入先展示缩略图与转录卡。不确定段落高亮并提供“确认无误 / 修改转录”，确认前不显示“已写入学习档案”。
- 需要副作用确认时，在消息流内显示 diff 卡，同时打开确认对话框并显示 120 秒倒计时。原 SSE 保持连接；用户提交决定后原消息流继续。断线、超时或后端重启均显示为“本次操作已拒绝”，不提供虚假的恢复入口。

**输入区**

- 多行输入框默认 48px，最多增长到 180px；支持拖入对话图片、粘贴截图和选择本地图片，单附件上限 10 MiB。
- 左侧附件按钮，右侧发送按钮；输入框上方显示待上传文件和 OCR 能力状态。
- 首版只接受文字与图片，不显示麦克风或语音转写入口。
- 提供少量上下文相关建议，如“继续上次内容”“生成三道练习”，不固定展示大块 prompt 模板。
- 流式生成时发送键变为停止键；停止后保留已生成内容并标记“回答已中断”，允许继续。

**开场与空态**

- 新会话显示课程名、上次学习摘要和最多三个建议动作。
- 无历史时使用一句主文案：“今天想从哪里开始？”并提供“问教材 / 做练习 / 制定计划”。不使用机器人插画。

### 4.2 知识仓库：RAG 资料库与 Wiki

知识仓库是全局导航，但所有材料与知识页必须位于用户显式选择的课程。未选择课程时显示课程选择/新建入口，不聚合跨课程资料。页面顶部选择课程，主体提供同等层级的“RAG 资料库 / Wiki 知识页”双 tab，默认进入 RAG。

**RAG 资料库（默认）**

1. 用户拖入或选择文件，前端立即显示格式、大小和页数校验。
2. 上传成功后自动开始 RAG 索引与概念目录构建；状态依次为“上传中 / 校验中 / 提取文本 / 切块 / 嵌入 / 建立索引 / 可检索 / 失败”。依赖不可用而使用词项检索 fallback 时必须明确标注，不能伪装为向量嵌入完成。
3. 每本教材显示文件名、版本、页数、索引时间和操作菜单；失败可重试，不要求重新上传已成功保存的文件。
4. 提供“检索验证”输入框，结果展示材料、页码/chunk、分数和当前 retrieval backend，帮助用户确认 RAG 是否真的可用。

**Wiki 知识页（同级可选 tab，默认关闭）**

- 课程级“启用 Course Wiki”开关默认关闭，并标注“实验功能”。关闭时不触发 Wiki 解析，不影响 RAG 检索与聊天。
- 首次打开时用短说明确认：Wiki 会从教材生成概念页，内容可检查、编辑和关闭；不会覆盖用户手写区块。
- 开启后，每本已完成索引的教材显示主操作“解析到 Wiki”；同时提供“解析全部已索引教材”的次级操作。
- 点击后先展示预计影响：新增/更新教材数与将要运行的步骤，再启动后台任务。任务卡展示“提取目录 → 概念候选 → 页面草稿 → 待确认”。
- 概念合并、拆分或与旧概念冲突时进入待确认列表；确认前不改稳定 `concept_id`。
- 关闭 Wiki 只停止生成和入口展示，不删除已有页面；删除数据必须进入独立危险操作并二次确认。

**Wiki 阅读页**

- 左侧概念目录，中间 Markdown 正文，右侧“来源 / 历史 / 学习状态”标签页。
- 掌握情况显示“数据不足 / 学习中 / 较稳定 / 需复习”以及证据数、最近证据日期，不单独用颜色或百分比下结论。
- Git 历史以时间线和逐行 diff 展示；用户编辑区与 Agent 管理区有明确标签。

### 4.3 计划

- 默认进入“今天”视图：完成进度、今日条目、预计时长和近期到期复习。
- 桌面端支持周日历；移动端优先日程列表。月视图仅用于总览，不承载复杂编辑。
- 计划条目显示学习/练习类型、时间、关联概念 chip、完成状态和推送状态。
- 编辑未来条目时先在侧边抽屉修改，再展示 diff；历史条目只读并标明“历史记录不可修改”。
- 自动重排建议以横幅呈现原因和影响范围，用户可“查看调整 / 暂不调整”；复合掌握分只作参考，触发原因写成可理解信号，如“连续两次答错”或“复习已到期”。
- 无计划时使用三字段引导：考试日期、范围、每周可用时间；生成后仍需用户确认再启用提醒。
- 定时任务使用的课程隐藏系统会话不出现在会话侧栏，也不产生未读角标；用户只在计划条目的“推送记录”中查看生成与投递结果。

### 4.4 学习档案

页面包含“概览、概念、错题与复习、证据”四个标签页。

- 概览只保留四类信息：本周学习、近期进展、待复习、计划完成情况。
- 概念列表支持章节、状态和证据数筛选；状态标签与时间趋势比单一分数更突出。
- 点击概念打开证据抽屉，按时间显示题目、作答、评分、用户标记与订正关系；允许提交纠错，但不物理删除历史。
- “高频未归因主题”作为管理入口，帮助用户补录或关联概念；不要让 `unattributed` 事件静默消失。
- 错题详情可跳回原会话或在当前工作区发起变式练习；课程工作区续接课程会话，通用工作区保持通用 scope 并由 turn context 限定该题所属课程。

### 4.5 Skill 上传与管理

Skills 设置页分为“已安装”和“上传”。上传调用 `POST /skills/import`，支持单个 `SKILL.md` 或包含它的 `.zip`；zip 可附带 UTF-8 的 `.md / .txt / .json` 只读参考文件，不允许上传后直接执行任意脚本。

上传流程：

1. 选择文件并做本地格式检查。
2. 后端校验 frontmatter、名称冲突、路径安全、文件类型、20 个文件/2 MiB 限制和 `allowed_tools`。
3. 预览名称、用途、触发条件、内容 hash、声明工具与文件清单。
4. 用户选择作用范围（全局或指定课程）后安装；**新上传 skill 默认禁用**。
5. 启用前再次展示它申请和最终获准的工具；越权工具直接阻止启用，而不是只警告。

Skill 卡展示“内置 / 用户上传”、启用范围、不可变版本、最近使用和健康状态。支持禁用、更新、导出与卸载；更新创建新版本并先展示权限 diff。`practice` 和 `wiki_curator` 标记为内置，默认不可卸载。上传页说明 skill 是操作规程，不是后台常驻 Agent。

### 4.6 IM 渠道设置

首版渠道页只展示一个 IM 渠道；“更多渠道”用一句后续说明，不展示任何尚未实现渠道的配置表单。

- 连接区：App ID、App Secret、连接测试和密钥保存状态；保存后 Secret 只显示掩码，不回显明文。
- 绑定区：生成绑定码或展示连接步骤，成功后显示 IM 用户与绑定时间。IM 渠道每个用户只有一个通用会话，不显示或保存“当前课程”；课程通过对话逐轮解析。
- 推送区：默认课程、每日上限、免打扰时段、每日任务/小测/周报三个开关。
- 预览区：使用真实 IM 消息卡片比例预览，不要求用户先发送测试消息。
- “发送测试消息”属于明确外部副作用，按钮文案直接表达动作，并在成功后显示 IM 回执。
- 断连、权限不足、事件订阅缺失要给出可执行修复步骤；用户关闭渠道时保留绑定配置，删除凭据是独立操作。

## 5. 核心组件与状态

| 组件 | 用途 | 必须覆盖的状态 |
| --- | --- | --- |
| `AppShell` | 全局导航与通用/课程工作区 | 展开、折叠、移动抽屉 |
| `WorkspaceSwitcher` | 通用模式与课程切换 | 通用、固定课程、课程已归档；切换不修改旧会话 |
| `SessionList` | 完整会话历史与课程色点 | 未解析、最近解析课程、固定课程、加载和空态 |
| `CourseBadge` | 显示绑定课程 | 正常、课程已归档、不可切换提示 |
| `ConversationStream` | 消息与 SSE | 连接、生成、等待确认、中断、失败、完成 |
| `Composer` | 文本与图片输入 | 空、上传中、发送中、达到限制、视觉未启用 |
| `CitationChip/Drawer` | 教材证据 | 加载、定位成功、原文缺失 |
| `ArtifactCard` | 展示公开的通用 artifact | 加载、可用、已失效；只依赖通用 envelope，不维护练习阶段或固定 payload schema |
| `AsyncJobCard` | RAG 索引与 Wiki 解析 | 排队、文本提取、切块、嵌入、索引、待确认、成功、fallback、部分成功、失败 |
| `DiffReview` | 计划/Wiki/Skill 更新 | 新增、修改、删除、冲突 |
| `MasteryLabel` | 学习状态 | 数据不足、学习中、较稳定、需复习 |
| `SkillCard` | Skill 生命周期 | 未校验、禁用、启用、更新可用、不可用 |
| `ChannelHealth` | IM 连接状态 | 未配置、测试中、在线、降级、断开 |

服务端是语义真源。前端状态管理只缓存查询结果、UI 展开状态和未发送草稿；课程绑定、计划版本、artifact、job 与审批状态均以 API 返回为准。SSE 断线后通过 messages API 读取已经持久化的完整或中断消息，不凭本地 delta 猜测完成状态；正在等待的审批按拒绝处理，不恢复 Agent 中间状态。

## 6. 动效、空态与错误态

### 6.1 动效

- hover/focus 120ms，抽屉与卡片变化 180ms，页面过渡最长 240ms；统一使用 `cubic-bezier(.2,.8,.2,1)`。
- 流式文本直接追加，不做逐字淡入；状态点可使用低频呼吸动画。
- 计划重排使用位置变化和 diff 高亮帮助理解，不使用庆祝粒子或大幅弹跳。
- 遵循 `prefers-reduced-motion`，关闭位移动画和无限循环动画。

### 6.2 空态

空态必须回答三件事：这里将出现什么、为什么现在没有、下一步能做什么。每个空态最多一个主按钮和一个文本链接。例如 Wiki 关闭时显示“Wiki 尚未启用”，主按钮“前往课程设置”，链接“了解 Wiki 与 RAG 的区别”。

### 6.3 错误与恢复

- 表单错误贴近字段；跨页面错误使用通知条；不可恢复错误才使用模态框。
- 上传、索引、OCR、SSE 和 IM 连接分别使用稳定错误文案，展示“重试 / 修改配置 / 保留已完成结果”等下一步。
- `session_busy` 不显示通用 409，而显示“该会话正在生成回答”，并提供返回当前生成任务。
- `version_conflict` 重新拉取数据并展示新旧 diff，不静默覆盖。
- OCR 失败保留原图，允许重新识别或改用文字输入；Wiki 解析部分失败保留已成功页面。
- 图片超过 10 MiB、Skill 包超过 2 MiB 时在上传前拦截，并显示准确上限；后端拒绝仍使用相同文案，不能只依赖前端检查。
- 审批超时或连接断开后关闭确认框并显示拒绝回执；用户若仍希望执行，需要重新发起修改请求。

## 7. 可访问性

- 目标为 WCAG 2.2 AA；正文与背景对比度至少 4.5:1，大字号至少 3:1。
- 所有功能可通过键盘完成；交互元素有清晰的 2px focus ring，抽屉/对话框正确管理焦点与 Esc 关闭。
- 图标按钮必须有可读名称；状态不只靠颜色；表单错误通过 `aria-describedby` 关联。
- 流式回答不逐 token 播报给读屏器，只在句子边界合并播报或完成后通过 `aria-live="polite"` 通知。
- 教材与 Wiki 标题保持语义化层级；公式使用可访问的 MathML/KaTeX 输出；图表提供文字摘要。
- 点击目标至少 40×40px，移动端至少 44×44px；支持 200% 字体缩放且核心操作不丢失。

- [ ] 会话列表始终可见：固定课程使用稳定色点，通用会话保留通用图标并仅用最近成功解析课程着色，未解析时为中性灰。
