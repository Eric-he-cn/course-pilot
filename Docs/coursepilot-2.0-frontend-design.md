# CoursePilot 2.0 前端设计

本文补充 [产品设计](coursepilot-2.0.md) 与 [架构设计](coursepilot-2.0-architecture.md) 中的前端部分，作为 React SPA 的实现基线。目标是做一个安静、清晰、愿意长时间停留的个人学习空间，不做功能堆叠的管理后台。

§1–§7 描述已经落地的界面，真源是 `frontend/src/App.tsx`、`frontend/src/styles.css`、`frontend/src/i18n.ts`。设计已定、代码里还没有的部分集中在 §8，正文不重复。

## 1. 视觉方向与设计原则

视觉识别方案代号 **Terminal**，落地于 `frontend/src/styles.css`。总体原则：

- 避免大面积渐变、霓虹和“AI 紫”；分区靠细边框，不靠浮起卡片。
- 内容优先。聊天、教材原文、公式和计划占据视觉中心，导航与工具在需要时出现。
- AI 行为可见但不过度打扰：检索、调用 skill、更新档案以简短状态或回执呈现。原始思维链只在开发者模式的 trace 侧栏里出现，日常界面不展示。
- 重要状态同时使用文字、图标和颜色表达；掌握度不只显示一个看似精确的百分比。
- 不制作高成本品牌插画。空态使用排版、细线图标和一张简洁内容卡即可。
- 同一课程使用稳定的小色标辅助识别，但所有课程仍共享统一主色与组件体系。

### 1.1 概念

**开发者工具的浅色模式**（Linear / Vercel / Raycast 一系）：纯白画布、锐利细边框、等宽字体承担元数据、把「系统正在做什么」当作设计语言的一部分。这与产品强调证据、引用、trace、可审计的理念一致——界面本身就应该透明、精确、可信。

国际化、极简、极客；明确反对：AI 通用风（渐变、AI 紫、大圆角胶囊、弥散阴影）、中文字 logo、彩色装饰。

### 1.2 识别元素

1. **方块标记 + 字标**：黑底圆角方块，内部是一条白色折角与一条主色基线——折角读作「一页纸翻起的角」，基线读作光标停在行首，和界面里的 `❯` 提示符是一套语汇。纯几何，无字符无汉字。字标 `CoursePilot` 用系统字体，只做两处排版微调：字距 -0.022em、`Course` 450 / `Pilot` 680 的双字重。出现在登录页与侧栏顶部；版本号只在状态栏右下角出现一次，品牌区不重复。favicon 是同一个标记的 16px 简化版（去掉折角斜线，那个尺寸会糊）。
2. **`❯` 提示符**：Agent 回答头部（`❯ CoursePilot`）、输入框前缀、空态标记，唯一的「角色」符号。
3. **等宽元数据层**：等宽只承担机器事实——时间、页码、token 数、耗时、文件名、skill id、`PDF` 角标、`v2.0`。含中文的文案一律无衬线：等宽字族不含 CJK 字形，中文放进去会静默掉到后备字体，既不对齐字重也偏细。trace 侧栏里的 `<pre>`（模型原文与 JSON）例外，等宽在那里表达「未经排版的原文」。
4. **依据面板**：回答末尾一块面板，标题「依据」+ 按类别的计数（`教材 2 · 知识页 1`）。一行一条来源，左侧 3px 语义色条区分类别（教材墨色、知识页 `--wiki`、网络 warning），出处右对齐成列（`p.4` / `转述` / `网络`）。色条比颜色深浅可靠：色觉障碍下也分得出。网页那条的名字带点状下划线，表示点开会离开本页。
5. **底部状态栏**：常驻一条 26px 状态栏，展示连接状态、模型与思考档位/深度、界面语言，右下角是版本号。数据读 `/health`，掉线时除连接状态外全部隐藏，不留缓存旧值。检索 backend 与「回答优先用当前课程资料」那类行为说明都不放这里——状态栏只放系统状态，前者收到知识库页顶部。
6. **戳记状态**：状态标签为小字 + 1px 描边，无填充底色。
7. **课程色条**：课程标识统一为 2.5–3px 竖色条（侧栏、顶栏、页面 hero、课程选择卡、设置页共五处）。实心圆是整套界面里唯一的实心饱和色块，和「分区靠细边框不靠填充」冲突；竖条与 tab 那条 2px 主色下划线是同一个手势。

### 1.3 设计 token

`styles.css` 的 `:root` 是唯一一份 token 定义，组件不写死颜色。

```css
--bg:     #FFFFFF   /* 画布：纯白 */
--panel:  #F8FAF9   /* 面板：侧栏、气泡、代码块。中性色带极轻绿偏，和主色同源 */
--text:   #18181B
--muted:  #6B7472
--border: #E3E7E5   /* 1px 锐利边框，分区只靠它 */
--accent: #047857   /* 终端绿：只用于 icon、提示符、激活态、状态点。
                       原来的 #059669 在白底上 3.77:1，达不到正文级 4.5:1，压深后 5.48:1 */
--wiki:   #8B9490   /* 知识页色条。白底 3.12:1 过图形门槛；做文字色不够，只用于色条 */
--danger: #DC2626
--warning:#B45309
--shadow: 0 1px 2px rgb(0 0 0 / 4%)      /* 贴地投影，唯一允许的阴影级别 */
--focus:  0 0 0 3px rgb(4 120 87 / 22%)  /* 键盘焦点环，跟着 --accent 走 */
--stack-0..6                             /* 上下文堆叠条的 7 级，按占比降序取用 */
```

- 圆角 6–8px；表意性圆形控件（开关、未读点、思考三点）除外。浮层（引用抽屉、trace 侧栏、上下文气泡）使用更重的投影，普通卡片只靠边框与留白分层。
- 主题色不做大面积填充；索引流水线「进行中」步骤与开关打开态允许 accent 实底。
- 课程色由服务端下发，仅用于竖色条；通用模式的会话列表里兼作未读点的颜色（颜色管归属、形状管状态）。
- 深色模式不作为首版发布条件。

### 1.4 字体

```css
--sans: system-ui,-apple-system,BlinkMacSystemFont,"Segoe UI","Helvetica Neue","PingFang SC","Microsoft YaHei","Noto Sans SC",sans-serif
--mono: ui-monospace,"SF Mono",SFMono-Regular,Menlo,Consolas,monospace
```

| 用途 | 字族 | 规格 |
| --- | --- | --- |
| 页面标题 / hero | sans | 24px，字重 650，字距 -0.02em（窄屏 21px） |
| 正文（含 Agent 回答） | sans | 15px / 行高 1.78 |
| 时间、页码、token 数、耗时、文件名、skill id | mono | 10–12px，tabular-nums 对齐 |
| 卡片标题 | sans | 15px，字重 600 |
| tab、导航项、侧栏行 | sans | 13–14px |

只用系统字体栈，不引入 webfont。

### 1.5 组件规范

- **按钮**：主按钮墨底白字 6px 圆角；次级按钮白底 1px 边框；破坏性操作红字。
- **输入区（composer）**：1px 边框 + 贴地投影，左侧 `❯` 绿色提示符；聚焦时边框变 accent。
- **选中态**：白底 + 1px 边框 + 贴地投影（浮出面板），不用填充色表达选中。
- **tab**：底部 2px accent 下划线表示激活，未激活为灰字，无填充底色。
- **依据面板**：回答末尾的面板，标题「依据」+ 分类计数；一行一条、左侧语义色条、出处右对齐成列。教材与知识页点开右侧引用抽屉，网页直接开新标签页。
- **索引流水线**：mono 戳记步骤，已完成=墨字，进行中=accent 实底白字，未开始=灰字；进度条 4px accent。
- **危险操作**：删除课程、教材、MCP server 一律先展开红框确认卡，逐条列出连带影响，再让用户点。
- **空态**：`❯` 符号 + 标题 + 一句说明，不用插画。

### 1.6 动效

- 只保留必要过渡：侧栏收合与移动抽屉 180ms、开关滑块 180ms、trace 侧栏滑入 180ms、进度条宽度 400ms 线性。
- 不做入场动画、骨架屏闪烁和渐变流光。流式文本直接追加，末尾一个闪烁光标块表示还在写。
- 唯一的循环动效是工具 chip 的呼吸点与「正在思考」的三点，`prefers-reduced-motion` 下全部关闭并保持完全不透明。

### 1.7 禁止清单

- 渐变、玻璃拟态、弥散阴影、大圆角胶囊。
- 中文字或表意字符作为 logo / 图标。
- 彩色填充的状态标签与 chip。
- 装饰性 emoji / 插画作为界面元素。
- 状态栏展示假数据；所有系统信息必须来自真实接口。

## 2. 信息架构

单页应用，没有路由：视图是 `App` 里的一个 `view` 状态（`chat` / `library` / `plan` / `archive` / `settings` / `help`），工作区是另一个状态（通用或某门课）。地址栏始终是根路径，没有深链，刷新回到默认视图。

```text
登录（只输用户名，用于分开存资料，不做访问控制）
└─ 主框架
   ├─ 侧栏
   │  ├─ 工作区：通用模式（罗盘图标 + 副标题）· 课程列表（竖色条）· 新建课程
   │  ├─ ——— 唯一的分隔线，落在工作区与它的内容之间 ———
   │  ├─ 对话 · 知识库 · 学习计划 · 学习档案（线性图标，无小标题）
   │  ├─ 会话：当前工作区的会话（未读状态位）+ 新建会话
   │  └─ 页脚：使用说明 · 切换用户 · 管理与设置
   ├─ 顶栏：折叠/抽屉按钮 + 会话标题（可就地改名）+ 工作区色条与名称
   ├─ 内容区：上面四个学习页 + 使用说明 + 管理与设置
   ├─ 状态栏：连接 · 模型/思考 · 界面语言 · 版本号
   └─ 右侧浮层（同时只开一个）：引用抽屉 380px · trace 侧栏 560px
```

侧栏顶部是「工作区」组：通用模式与各门课在同一组、同一行式、同一选中态——它们互斥单选，写的是同一份状态。通用模式不是一门课，这件事靠罗盘图标与副标题「按问题自动判断课程」表达；课程带稳定颜色的竖色条。分隔线只有一条，落在这一组与它的内容（页面、会话）之间——层级断点在那里，不在通用模式与课程之间。页面那四行不加小标题，线性图标已经说清它们是导航。切换只改变当前浏览工作区并重新拉取该 scope 的会话，不修改旧会话。会话列表按当前工作区过滤（`GET /sessions?scope_mode=&course_id=`）；课程工作区里所有会话必然同色，所以那一列不显示归属色，标识槽让给未读状态，只有通用模式才用课程色表达归属。

通用会话在对话页顶部显示逐轮解析结果：「本轮解析到某课程」或「尚未确定」；课程会话不显示这一条，课程已由顶栏色条与名称表达。`resolved_course_id` 只用于列表色条，不能在前端被解释成永久绑定。

从知识库、计划、学习档案任一页进入时若还没选课程，页面本身变成课程选择器（`❯` + 课程卡网格 + 新建课程），选中后留在当前页。

「管理与设置」和「使用说明」不进主导航，收在侧栏页脚。模型与思考档位是日常要调的，放在状态栏；trace 这类开发者信息由「管理与设置 → 开发者模式」的开关控制，关掉时界面上没有入口可点。

## 3. 响应式布局

### 3.1 桌面端

- `≥ 960px`：左侧栏 252px 固定，可折叠为 72px 图标栏，折叠状态存 `localStorage`。
- 主内容区左右内边距 `clamp(20px,4vw,48px)`，页面内容最大宽度 1120px。
- 对话正文与输入区共用 `min(68ch,690px)` 列宽（`max(20px,(100% - min(68ch,690px))/2)` 居中），实测 15px 中文约 40–45 字/行；用户气泡最宽 72%。
- 右侧浮层为覆盖式：引用抽屉 `min(380px,94vw)`，trace 侧栏 `min(560px,96vw)`。两者同时只开一个。
- 底部状态栏固定 26px。

### 3.2 窄屏

- `< 960px`：侧栏变成左侧全高抽屉（右留 18% 露出背景），顶栏出现 ☰ 按钮，点背景蒙层关闭；状态栏只留连接状态，下拉与检索信息隐藏；知识库与设置的双列网格压成单列；两个右侧浮层顶部下移 46px 让出顶栏。
- `< 520px`：hero 标题降到 21px；资料行折成两行，尾部按钮与状态标签左对齐；检索验证的输入与按钮改成上下排列。
- 对话输入区吸附在对话流下方，随窄屏收窄内边距；键盘弹出时靠浏览器默认行为保持输入框可见。
- 计划页的周网格在 720px 以下改成纵向一天一行，无任务的日子收起（按 `:not(:has(.task))` 判——每格里都有一个 `<time>`，`:empty` 匹配不到）；日程列表按天分组。

## 4. 核心页面

### 4.1 对话主界面

结构为「会话侧栏 + 对话正文 + 可选右侧浮层」。

**顶部栏**

- 会话标题可点开就地改名（Enter 提交、Esc 取消），右边是工作区色条与名称。
- 通用会话的逐轮解析结果在对话流上方单独一条，不挤进顶栏。

**消息流**

- 用户消息使用浅色实心气泡；Agent 回复采用无气泡正文，提升长文、公式和引用的阅读体验。
- Agent 回复以 `❯ CoursePilot` 开头。开发者模式打开时这个名字是按钮，点它先弹一句二次确认，确认后从右侧滑出这一轮的 trace。
- 正文按 Markdown 渲染，支持 GFM 表格（宽表套横向滚动）、KaTeX 公式、mermaid 代码块（渲染成图并提供下载 SVG；流式期间代码不完整时保留源码，防抖 400ms 后再渲染）。
- 工具过程合并成一排 chip：工具名 + 一句摘要 + 耗时，进行中显示呼吸点与自增秒数。服务端每轮自动做的种子检索只在命中时占一行；未命中与被停止的占位不上屏。
- 三类引用收在文末的依据面板里（标题「依据」+ 分类计数，一行一条、左侧语义色条、出处成列）。教材与知识页点开右侧抽屉；知识页抽屉头部写明这是转述稿、没有页码，底下按文档列出它依据的教材页（`文档 第 9–11 页`），点某一页转成教材原文抽屉。网页引用只允许 http(s)，直接开新标签页。
- 服务端下发选项时（`ask_user`）在消息末尾渲染成一排按钮，点击等于发一条新的用户消息。完整题干必须在正文里，选项按钮只是快捷方式。
- 远端模型不可用而降级到本地兜底时在消息里明说，避免把质量完全不同的回答当成正常回答。
- 流式生成时发送键变为停止键；停止后保留已生成内容并标明它可能没有保存，同时给一个「重试」按钮重发对应的提问。中断的消息同样带重试入口。
- `practice` 的题目、作答与讲评沿用普通 Markdown 消息；服务端返回的公开 artifact 只按 `kind` 做轻量容器展示，不假设固定的题目、答案或评分 schema。`visibility=model_private` 的 payload 永不进入前端。

**输入区**

- 多行输入框最小 46px，用户可拖拽调高；Enter 发送、Shift+Enter 换行，中文输入法组合期间不误发。
- 左侧「图片」按钮选本地图片（png/jpeg/webp）。上传后在输入框上方显示转录卡：`IMG · 文件名` + 转录文本；没识别出文字的那张标黄并提示在消息里补充说明。切换会话时丢弃不属于新会话的附件。
- 上下文占比环在发送键左边：14px SVG 环 + 百分比（过阈值整枚转琥珀），点开是堆叠条 + 按占比降序的分段列表，占比小于 2% 的折成一行，点开才展。分段构成（系统提示、工具定义、知识页目录、能力摘要、长期记忆、会话历史、当前问题、教材证据、知识页正文、工具结果等）。口径是 token 估算（中日韩 1 字 1 token，其余 3.5 字符 1 token），并显式说明这是估算值。历史被丢弃、被截断、某一段超限被压缩、总闸生效时各自打一条警示行。
- 首版只接受文字与图片，不显示麦克风或语音转写入口。

**开场与空态**

- 无历史时显示 `❯` + 「今天想从哪里开始？」+ 一句 scope 说明，附三个建议：讲讲这门课的核心概念 / 给我出几道练习题 / 帮我制定复习计划（通用会话第一条换成带课程名占位的问法）。点建议填进输入框，不直接发送。
- 不使用机器人插画。

### 4.2 知识库

知识库是全局导航，但所有材料与知识页必须位于用户显式选择的课程。未选择课程时页面显示课程选择器，不聚合跨课程资料。页面顶部是课程名与检索 backend 徽标，主体四个同级 tab，默认进入「RAG 资料库」。

**RAG 资料库（默认）**

1. 上传单个文件（pdf / txt / md / doc(x) / ppt(x)），前端拦截超过 100 MiB 的文件，上传成功后自动排索引任务。
2. 索引流水线画成五个戳记步骤：解析 → 切块 → 向量 → 索引 → 目录。前四步是检索索引，最后一步是概念与层级，两条流水线共享前面的文本准备。任务进行中显示步骤与 4px 进度条。
3. 扫描版 PDF 停在「需要 OCR」并等确认：先给账单（页数、取样实测的 token 与秒数、按页数外推的总量与耗时），实测行与外推行分开写，用户点确认才花额度。
4. 每份教材显示类型标记、文件名、大小、切块数与检索方式（语义或词项），失败展示报错并可重试，不要求重新上传已保存的文件。删除走危险确认卡。
5. 「检索验证」输入框直接打一次检索，结果展示材料、页码、原文片段和分数，帮助用户确认 RAG 是否真的可用。

**概念目录**

两张卡。上面是「目录结构」：每份教材一行，说明它有没有层级、抽出多少概念，并给出解析或重算入口。重算是独立流水线，只读已落库的正文，不重新提取、不重新生成向量。点重算先给影响预告——新增、保留、删除各多少个概念，将被删掉的概念名（超过 8 个折成「另 N 个」），其中多少个带着掌握度或错题记录会一起丢掉，以及这次能不能拿到层级——确认后才执行。

下面是「概念目录」树：层级来自教材自带的目录书签，按 `parent_id` 分组渲染，有子项的行才有折叠箭头，右上角一键全展开/全折叠。没有书签的教材（讲义、扫描件）抽出的概念是平的，界面直说这件事，不假装有层级。frontmatter 被手改成父子互指时，环里的节点提回根节点显示，一行都不少。

**Wiki 知识页**

- 课程级「启用 Course Wiki」开关默认关闭，标注「实验功能」。关闭时 tab 名后缀「（已关闭）」，内容区是空态「Wiki 尚未启用」+ 一句「不开也不影响提问与检索」。
- 开启后，每份已索引的教材一行，先给离线算出的账单：预计页数、模型调用次数、约几分钟，若有同页合并或缺层级也在这里说明。账单不花额度，教材内容变过之后才作废重算。
- 点「生成知识页」进后台任务，行内显示「正在写第 12/51 页」与进度条。收尾时报覆盖率：共几个小节、生成了几页、写入与跳过各几页。
- 已生成的页按教材目录嵌成可折叠树（与概念目录同一套树组件），点标题在卡内展开正文，frontmatter 不渲染给用户看。没有层级的教材照旧平铺。
- 关闭开关只停止生成与入口展示，不删除已有页面。

**课程笔记**

助手用 `note_write` 落盘的学习卡片与整理稿，按课程分目录存在用户工作区里。列出标题、字数和更新时间，点开在卡内渲染 Markdown。没有笔记时说明怎样才会产生笔记（对助手说「做成学习卡片」「存下来」）。

### 4.3 学习计划

计划由对话产生：用户在对话里要求排计划或改计划，助手用 `plan_update` 写库，每次改动升一个版本。计划页是这份数据的只读视图。

- 页头一句说明这条链路，卡片头部显示版本号、条目数和更新时间。
- 周网格是计划总览：有条目的周全部列出（不翻页，翻页会藏掉信息），每天一格，今天浅绿底 + 顶部主色线，任务卡按状态挂左侧色条（待做/已完成/补做逾期）。任务名不截断，长标题换行；概念名作副行。
  选型上甘特不合适：它表达跨度与依赖，而这里每条都是「某一天读某几页」，两者都没有。
- 下面是按天分组的日程列表，今天与过去两种日期各有标记，每条显示标题、状态和关联概念。
- 没有计划时空态说明「在对话里说要排计划」。读取失败给一张重试卡，重试真的重新发请求。

### 4.4 学习档案

单页四张卡，从上到下：概念掌握度、错题本、证据事件、未归因主题。

- **概念掌握度**：分数由服务端算（BKT 后验 × 遗忘曲线），左侧方块显示 0–100 或 `—`，下面是客观证据条数与下次复习日期，再下面一条进度条。证据不足的概念显示「数据不足（N 条客观证据）」并且不画进度条，不给一个看似精确的数字。
- **错题本**：按概念记账。每行显示累计错次、当前连对进度（「连对 1/2」，阈值随响应下发，前端不另存常量）、上次答错时间和一条进度条；反复错过的打「再犯」标签。列表只是一页，被截断的条数显式说出来。毕业的条目折进 `<details>`，计数始终可见——清掉的东西看得见，用户才知道这套机制在起作用。
- **证据事件**：按时间列出事件类型、概念名或主题线索、归因状态。
- **未归因主题**：`unattributed` 事件按主题聚合，显示命中次数与最近出现时间，避免这些事件静默消失。

### 4.5 使用说明

一页可读的能力清单，可数的内容全部来自接口，不做需要人工同步的死文档。

- 「上手三步」按真实状态勾选：有没有课程、有没有已索引的教材、有没有会话。
- 「两种会话模式」解释通用与课程 scope 的差别。
- 「专项能力」列出已启用的 skill（名称、内置或用户上传、用途、触发条件），skill 自带的示例问句是按钮，点一下带进对话输入框。
- 「当前实例状态」读 `/health`：模型、检索方式、联网开关、限额。
- 「它能碰到什么」把工具按能力分组（读课程资料 / 写状态 / 写笔记 / 联网 / 派子任务 / 无副作用），让权限边界一眼可读。
- 「不做什么」一段划清边界。

### 4.6 管理与设置

一页六张卡：

- **课程与教材**：课程列表 + 知识页开关状态；删除课程走危险确认卡，逐条列出连带删除的内容。
- **长期记忆**：`user.md` 与每门课的 `memory.md` 可读可编辑。下拉切范围，有未保存改动时明确标出，保存与放弃分开两个按钮；说明 `agent:managed` 区块的含义。
- **能力（Skill）**：列出内置与用户上传的 skill，显示用途、声明工具、被拒绝的工具和状态（已启用 / 待启用 / 权限不足）。用户上传的可启用、停用、删除；权限不足的直接禁掉启用按钮。上传支持单个 `SKILL.md`、`.zip` 或整个目录，被跳过的文件逐个报出来。内置 skill（`diagram`、`flashcards`、`mistake_review`、`practice`、`research`）不可删除。
- **MCP server**：填标签、URL、可选凭据即可接入。工具清单是点连接那一刻拉下来的快照，运行期只用这一份，server 事后改定义不会生效——这句写在卡上。每台显示来源（用户添加或模型提议）、URL、工具数、有无凭据、server 信息；快照阶段与下行阶段被丢掉的工具分别报数；连接失败显示错误码对应的说明。模型提议的 server 处于「待批准」，要用户点批准才连。删除走危险确认卡。凭据只写不回显。
- **开发者模式**：一个复选框。打开后 Agent 回复开头的名字变成可点的 trace 入口。开关存浏览器本地，只影响这台机器；关掉时整个入口不渲染，不留「按钮还在、点了没反应」的状态。
- **运行状态**：手动点「检查」拉一次 `/health`，展示模型、检索方式、嵌入模型加载情况、数据库迁移版本，原始 JSON 折在 `<details>` 里。

### 4.7 Trace 侧栏（开发者模式）

从右侧滑出的 560px 浮层，展示当前会话的轮次列表，点中的那一轮展开。它只做观测：trace 是可随时清理的旁路记录，读不到就照实说，不在界面上补出一份来。

**每一轮展开后的顺序**

1. 数据缺失先说：这一轮没有 trace 记录、payload 缺失或超限、点的那一轮不在扫描范围内，都在最上面标黄。
2. **ReAct 循环**（第一眼看的就是这一段）：
   - 「服务端注入的 `assistant(tool_calls)` + `tool`」单列在最前面（第一次模型调用之前发生的事）。
   - 之后每一次 chat completion 一张卡：`finish_reason`（厂商说的）与 `outcome`（服务端判的）两个 chip 分开摆，`injected` 单独一个 chip；`reasoning_content`（带上厂商实际用的字段名）默认收起，`assistant.content` 直接展示，`tool_calls` 按序号列在下面。
   - 每次调用显示工具名、来源、耗时、复用与拒绝标记，参数折在 `<details>` 里；`tool.content` 也是 `<details>`，**点开那一刻才去取那一条**，打开侧栏时不下载任何正文。正文没落库、被复用、被拒绝、失败、丢失各有对应的说明。
   - `delegate` 的子任务在父轮里只有骨架：几轮、每轮的思考与正文字数、调了哪些工具；它查到的正文单列在时序下面一栏。
   - 老 trace 的 span 没有 round，归不到某一步的调用单列在时序末尾，不藏掉。
   - 最后是这一轮的 `assistant.content` 全文。
3. **本轮的原始字段**折在最后并默认收起：轮次 id、开始时间、状态与错误码、耗时、提示词版本、scope、回答字符数、引用数/召回数、工具轮数，以及课程判定、responder、usage 和其余字段的原始 JSON。
4. 侧栏底部报扫描量（读了几个文件、几行）；覆盖不全时在顶部标黄，给出轮数、行数、文件数三个上限。

**入口的两道门**：开发者模式开着，且这条消息已经有 `turn_id`（流式中的临时消息还没有）。点名字先弹一句「查看这一轮的 Trace？」再打开。切换会话自动收起侧栏——轮次 id 属于上一个会话，留着只会显示成「这一轮没有记录」。

## 5. 组件与状态

`App.tsx` 是单文件组件树，主要组件与它们必须覆盖的状态：

| 组件 | 用途 | 必须覆盖的状态 |
| --- | --- | --- |
| `App` | 全局框架、工作区、会话、SSE 编排 | 侧栏展开/折叠/移动抽屉、在线/掉线、生成中、新建中 |
| `LoginView` | 用户名入口 | 空、超长、非法字符、记住上次用户 |
| `SessionRow` | 会话行 | 正常、改名中、删除确认、激活、未读（通用模式下带课程色） |
| `ChatView` | 消息流与输入区 | 空态、生成中、上传中、附件待确认、停止 |
| `MessageCard` | 一条消息 | 流式、停止、中断、降级、逐轮解析结果、artifact、选项 |
| `ToolChip` | 工具过程 | 进行中（自增秒数）、成功、失败、复用、种子检索隐藏规则 |
| `CitationPanel` / `CitationRow` / `CitationDrawer` | 三类来源 | 教材（页码/chunk）、知识页（无页码 + 出处页）、网页（外链）、原文缺失 |
| `ContextMeter` | 上下文占比 | 正常、历史被丢/被截、分段超限、总闸生效 |
| `LibraryView` | 知识库四个 tab | 上传中、轮询中、检索无结果、Wiki 关闭 |
| `MaterialRow` | 一份教材 | 已上传、流水线五步、需要 OCR、失败可重试、已索引（语义/词项） |
| `OcrEstimatePanel` / `StructurePreviewPanel` / `WikiEstimateNote` | 花钱或有破坏性之前的账单 | 估算中、可执行、执行中、空结果、有风险 |
| `ConceptTreePanel` / `WikiPagesPanel` | 两棵可折叠树 | 加载、空、平铺（无层级）、父子成环 |
| `PlanWeeks` / `PlanDays` | 计划视图 | 无计划、读取失败可重试、待做/已完成/补做逾期 |
| `MistakesCard` / `MistakeRow` | 错题本 | 空、全部清掉、被截断、已毕业折叠、再犯 |
| `MemoryCard` | 长期记忆 | 加载、干净、有未保存改动、保存中 |
| `SkillsCard` | Skill 生命周期 | 已启用、待启用、权限不足、导入被跳过的文件 |
| `McpCard` | MCP server | 未配置、待批准、已连接、已停用、连接失败、工具被丢弃 |
| `DangerConfirm` | 破坏性操作 | 列出连带影响后才允许确认 |
| `TraceDrawer` 及其子组件 | 开发者模式观测 | 加载、无记录、扫描被截断、点中轮次缺失、正文按需加载中/失败 |

服务端是语义真源。前端状态只缓存查询结果、UI 展开状态和未发送草稿；课程绑定、计划版本、artifact、job 状态均以 API 返回为准。几条已经踩过坑的约束：

- 流是异步的，用户随时可能切走。写消息前一律用 ref 判断「此刻」在看哪个会话，闭包捕获的值不行。
- SSE 正常结束后重新拉一次 messages 与 sessions，用服务端真值覆盖本地增量。被用户停止时保留本地已渲染内容并标明它可能没有保存。
- job 轮询只问未终态的任务，合并而不是整表替换结果，并且带一个 10 秒看门狗——请求永不 settle 时锁会永久卡住。
- `useMemo` 里调了 `t()` 的地方必须把 `lang` 放进依赖，否则换语言后缓存的旧译文会和现算的混排。

## 6. 动效、空态与错误态

### 6.1 动效

- 过渡统一 180ms + `cubic-bezier(.2,.8,.2,1)`：侧栏收合、移动抽屉、开关滑块、trace 侧栏滑入。
- 流式文本直接追加，末尾闪烁光标块；工具 chip 进行中呼吸点；等待第一个字时三点动画。
- `prefers-reduced-motion` 下把所有 transition 与 animation 压到 0.01ms，循环动效改为完全不透明的静态点——耗时数字这时是唯一还能说明「在动」的线索，所以它不是装饰。

### 6.2 空态

空态必须回答三件事：这里将出现什么、为什么现在没有、下一步能做什么。每个空态最多一个主按钮和一个文本链接。例如 Wiki 关闭时显示「Wiki 尚未启用」和一句「不开也不影响提问与检索」；课程笔记为空时说明对助手说什么才会产生笔记。

### 6.3 错误与恢复

- 全局错误用顶部通知条，可手动关闭；页面级读取失败用重试卡（重试真的重新发请求，不是只换文案）。
- HTTP 错误响应两种形状都认：`error` 在顶层、`detail` 是消息串是常态，少数端点抛嵌套形式。取错误码而不是匹配 message 文字，后端换措辞或翻译都不影响。
- 掉线由 15 秒心跳发现（掉线后 5 秒一探），只有真正拿到 `/health` 才算在线——开发时走 vite 代理，后端挂了拿到的是代理给的 500。掉线时状态栏隐藏所有缓存的旧值。
- 上传、索引、OCR、SSE 各自使用稳定错误文案，并给出「重试 / 保留已完成结果」这类下一步。索引失败保留已保存的文件，OCR 失败保留原图。
- 教材超过 100 MiB 在选择后立即拦截并报准确上限；后端拒绝时使用同一套文案。
- 用户名规则变严后本地存的旧名字不再合法时，认 `invalid_username` 错误码清掉本地值，让界面回到登录页。

## 7. 可访问性

- 目标为 WCAG 2.2 AA；正文与背景对比度至少 4.5:1，大字号至少 3:1。
- 交互元素统一 3px accent 焦点环（`--focus`），只在 `:focus-visible` 下出现。抽屉与确认框用 `role="dialog"` + `aria-label`。
- 图标按钮全部带 `aria-label`；状态不只靠颜色——工具 chip 的成功/失败/进行中各有符号与只给读屏器的文字说明，掌握度用「数据不足」而不是靠颜色暗示。
- 折叠树用 `aria-expanded` 表达开合；上下文占比环用 `aria-expanded` + `aria-label`；会话行的未读状态写进 `aria-label`，不只靠颜色与字重。
- 消息流是 `aria-live="polite"` 区域，流式文本按整块追加，不逐 token 播报。
- 公式走 KaTeX 输出；mermaid 图包一层 `role="img"` + `aria-label`，并提供下载原图。
- 装饰性字符与图标槽（`❯`、课程色条、罗盘与导航图标）一律 `aria-hidden`；折叠侧栏把文字收起，
  那时按钮改由 `aria-label` + `title` 提供名字。

**计划**

- 计划的编辑交互：侧边抽屉改未来条目、改动前的 diff、历史条目只读标记。现在计划页完全只读，改动只能通过对话。
- 月视图。现在是周网格 + 按天列表。
- 自动重排建议横幅（原因与影响范围、「查看调整 / 暂不调整」）。
- 无计划时的三字段引导（考试日期、范围、每周可用时间）。
- 计划条目的推送状态与「推送记录」。依赖调度与渠道，后端也没有。

**学习档案**

- 「概览 / 概念 / 错题与复习 / 证据」四个标签页与概览的四类汇总。现在是单页四张卡。
- 点概念打开证据抽屉（按时间显示题目、作答、评分、用户标记与订正关系），以及提交纠错。
- 掌握度的四档文字标签（数据不足 / 学习中 / 较稳定 / 需复习）。现在只区分「数据不足」与 0–100 的分数。
- 错题详情跳回原会话，或在当前工作区发起变式练习。

**Skill**

- 安装时选择作用范围（全局或指定课程）。
- 启用前展示「申请的工具 vs 最终获准的工具」的权限 diff。现在越权由 `permission_denied` 状态直接禁掉启用按钮。
- 不可变版本号、最近使用时间、健康状态、导出、更新时创建新版本。

**IM 渠道设置（整节）**

首版渠道页只展示一个 IM 渠道，「更多渠道」用一句后续说明，不展示任何尚未实现渠道的配置表单。代码里没有渠道模块，会话来源目前只有 Web。

- 连接区：App ID、App Secret、连接测试和密钥保存状态；保存后 Secret 只显示掩码，不回显明文。
- 绑定区：生成绑定码或展示连接步骤，成功后显示 IM 用户与绑定时间。IM 渠道每个用户只有一个通用会话，不显示或保存「当前课程」；课程通过对话逐轮解析。
- 推送区：默认课程、每日上限、免打扰时段、每日任务/小测/周报三个开关。
- 预览区：使用真实 IM 消息卡片比例预览，不要求用户先发送测试消息。
- 「发送测试消息」属于明确外部副作用，按钮文案直接表达动作，并在成功后显示 IM 回执。
- 断连、权限不足、事件订阅缺失要给出可执行修复步骤；用户关闭渠道时保留绑定配置，删除凭据是独立操作。
- 定时任务使用的隐藏系统会话不出现在会话侧栏，也不产生未读角标；推送结果只在计划条目的「推送记录」里查看。

**其他**

- 深色模式。前提还差一步：token 集中在 `:root` 了，但 `:root` 之外仍有 31 处硬编码色值、12 种（`#D4D4D8`×6 `#fff`×6 `#FCA5A5`×5 `#D1FAE5`×3 `#FEF2F2`×3 `#FFFBEB`×2，以及 `#0B0D0C` `#2D2D31` `#A7F3D0` `#F2FAF6` `#FCD34D` `#FDE68A` 各一处），集中在危险确认、警告提示、开关、hover 态、加粗文字与「今天」高亮。要上深色得先把它们收进 token——一次不产生任何视觉变化的重构，省不掉。

## 10. 验收清单

**框架与导航**

- [ ] 新用户无需阅读说明即可完成建课、上传教材、建立索引并开始第一次对话。
- [ ] 默认进入通用模式；左栏可切通用/课程工作区，切换不修改旧会话 scope，并重新拉取该工作区的会话。
- [ ] 会话行在通用模式下用课程色表达归属；未读有状态点与更重的标题字重；改名与删除在悬停时出现，删除有确认。
- [ ] 侧栏折叠状态刷新后保持；`≥960px` 布局无横向溢出，959px 与 390px 下无关键内容遮挡。
- [ ] 从知识库/计划/档案进入时未选课程会显示课程选择器，选中后留在当前页。
- [ ] 掉线时状态栏只留连接状态，不展示缓存的模型与检索信息；恢复后自动回到在线。

**对话**

- [ ] 三类引用视觉可分：教材带页码、知识页标「知识页 · 概念名」且抽屉里写明没有页码、网页带下划线且开新标签页。知识页引用能列出它依据的教材页并点开原文。
- [ ] 种子检索未命中与被停止的占位不上屏；模型自己发起的检索（含失败那次）照常显示。
- [ ] 上下文占比环的分段与总量来自服务端实际组装结果，口径写明是 token 估算；历史被丢/被截、分段超限、总闸生效各有可见提示。
- [ ] 停止生成后保留已生成内容、标明它可能没有保存，并能一键重发对应的提问。
- [ ] 降级到本地兜底模型时消息里明说。
- [ ] `ask_user` 的完整题干在正文里，选项按钮只是快捷方式。
- [ ] practice 不依赖前端硬编码阶段或题目/评分 schema；刷新后能由服务端消息与公开 artifact 恢复，私有 artifact 不可见。
- [ ] 对话只展示文字与图片入口；没识别出文字的图片有明确提示。

**知识库**

- [ ] 导航名称为「知识库」，进入后显式选择课程，默认显示 RAG 资料库；上传、提取、切块、嵌入、索引、目录结构六个状态与检索验证完整可见。
- [ ] 花额度或有破坏性的动作一律先给账单再执行：OCR（实测取样与外推分开写）、重算目录结构（新增/保留/删除，以及会连带丢掉掌握度或错题的概念数）、生成知识页（页数、调用次数、分钟数）。
- [ ] 概念目录与知识页两棵树的层级、折叠、全展开行为一致；没有层级的教材明说是平铺，不假装有层级。
- [ ] Wiki 每门课程默认关闭；上传教材不会自动生成知识页；构建由用户明确点击；关闭开关不删除已有页面。
- [ ] Wiki 关闭、未配置 OCR 时，文本学习与 RAG 均可正常使用。
- [ ] 教材与课程的删除都要先列出连带影响再确认。

**计划与档案**

- [ ] 计划页只读，页头说清「改动通过对话发生」；周网格与日程列表对同一份数据一致，待做/已完成/补做三种状态可分。
- [ ] 掌握度证据不足时显示「数据不足」并且不画进度条，不给看似精确的分数。
- [ ] 错题本的连对阈值来自响应；被截断的条数显式说出来；已清掉的条目折叠但计数可见。
- [ ] `unattributed` 事件在「未归因主题」里可见，不静默消失。

**设置与开发者模式**

- [ ] 用户上传的 Skill 在权限校验通过前不可启用；越权工具直接禁掉启用按钮；内置 skill 不可删除。
- [ ] MCP server 的工具清单是连接时的快照，界面写明这一点；模型提议的 server 处于待批准且需用户点批准；凭据只写不回显；被丢弃的工具分阶段报数。
- [ ] 开发者模式关闭时页面上没有 trace 入口可点；打开后点 Agent 名字先二次确认。
- [ ] trace 侧栏第一眼是 ReAct 循环，`finish_reason` 与 `outcome` 分开展示；统计与 usage 折在最后。
- [ ] `tool.content` 只在点开那一步时请求；打开侧栏本身不下载任何正文。
- [ ] trace 读不到、被截断、点中的轮次不在范围内时照实说明，不在界面上补出一份记录。
- [ ] 切换会话自动收起 trace 侧栏；引用抽屉与 trace 侧栏不同时出现。
- [ ] 长期记忆可读可编辑，有未保存改动时明确标出。

**通用**

- [ ] 界面语言可在状态栏切换，刷新后保持；英文态下后端下发的文案按 key 本地化，缺 key 时降级到中文原文而不是空白。
- [ ] 所有核心路径可键盘操作，焦点环可见，状态不只依赖颜色，屏幕阅读器不会逐 token 被刷屏。
- [ ] `prefers-reduced-motion` 下无循环动效，且仍能从耗时数字判断任务在进行。
- [ ] 页面使用统一 token，无散落品牌色、随机圆角和超过 240ms 的常规动效。
- [ ] 首版不依赖高成本插画、三维资产或复杂数据可视化即可达到完整质感。
