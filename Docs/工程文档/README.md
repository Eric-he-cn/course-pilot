## 维护约定

### 写作

- 文档呈现**当前最新的结论**，不留修订记录。发现之前写错了直接改对。
- 结论和推断分开写。"实测 X 次里有 Y 次"是依据，"大概是因为"是推断。
- 每份文档开头用「覆盖的代码」表交代它对应哪些文件，紧跟一行「相关：」链到有交集的文档。
- 每份文档以「设计取向」收尾，讲这套设计一以贯之的几条。
- 同一个机制只在一份文档里展开，其余文档链过去，不各写一遍。

### 配图

**优先用 mermaid 内联。** 流程、状态机、结构关系都用 ` ```mermaid ` 代码块直接写在正文里——它能 diff、能跟着代码一起改，GitHub 与编辑器都直接渲染。

**图要有结构才画。** 平行罗列的几条用列表或表格，画成一排没有连线的方框只是把文字重排了一遍。

配色已形成约定，新图沿用：

| 色值 | 用于 |
| --- | --- |
| `#e8f4ea` | 好结果、放行、成功路径 |
| `#fbeee8` | 危险、错误、不该发生的事 |
| `#fdf0e3` | 注意、降级、需要留心的分支 |
| `#eef5ee` | 中性强调 |
| `#e8eef8` | 中性分组 |
| `#eef0f6` | 旁路、存储 |

`images/` 只放 mermaid 表达不了的：界面截图、需要精确排版的示意图、外部素材。命名 `<文档名>-<序号>-<说明>.png`，例如 `工具系统-01-权限链.png`。序号按文档内出现顺序，方便重排时一眼看出缺哪张。

引用时用相对路径：

```markdown
![权限链](images/工具系统-01-权限链.png)
```

界面截图另有去处——`Docs/images/` 由 `scripts/screenshots.py` 生成，供 README 使用，不要手工往里放图。
