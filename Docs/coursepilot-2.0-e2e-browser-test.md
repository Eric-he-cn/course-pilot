# CoursePilot 2.0 浏览器端到端测试

一次浏览过程覆盖《Demo 交付计划》第 5 节的全部验收项，外加工具循环、跨语言检索和图片提问。

教材是真实开源教材的章节切片，断言锚点都是教材里真实存在的事实与页码；回答里出现这些事实，
才说明证据真的被检索到，而不是模型凭通用知识说出来的。

## 1. 前置

### 1.1 选驱动工具

| 工具 | 能否跑完整轮次 | 说明 |
| --- | --- | --- |
| playwright MCP | 能 | 首选。有 `browser_file_upload` 传教材、`browser_handle_dialog` 应答新建课程的 `window.prompt` |
| claude-in-chrome | 能 | `file_upload` 只接受用户已共享目录，需要 `--out ~/Documents/coursepilot-e2e` 生成 fixture |
| 内置 Browser pane | 不能 | 没有文件上传能力，只能跑第 6 步以后的对话部分 |

### 1.2 准备数据与启动

```bash
.venv/bin/python scripts/e2e_fixture.py
```

首次执行下载约 68 MB 开源教材，缓存在 `data/e2e-fixtures/source/`，重跑不再下载；随后切出章节、
光栅化一页 PNG，并清空 `data/e2e`。测试用独立数据目录，不碰开发库 `data/coursepilot.db`。

启动被测实例：`preview_start` 选 `coursepilot-e2e`，或

```bash
STORAGE_DATA_DIR=data/e2e ./scripts/dev.sh
```

`.env` 里 `COURSEPILOT_ENABLE_REMOTE_LLM=1` 必须开启，否则第 6 步起测的是本地 responder。
BGE 向量模型需已在本地缓存，否则首次索引会卡在下载模型。

### 1.3 课程、教材与锚点

| 课程 | 教材文件 | 来源 | 锚点事实（切片内页码） |
| --- | --- | --- | --- |
| 大语言模型 | `llm-微调-LoRA.pdf` | 复旦《大规模语言模型：从理论到实践》 | QLoRA 把预训练模型量化为 4-bit（p4–6）；AdaLoRA 针对"所有低秩矩阵共用一个秩"的问题（p4） |
| 大语言模型 | `llm-指令数据集.pdf` | 同上，表 5.1 | Super-NaturalInstructions：500 万条 / 多语言 / 手动构建（p1） |
| 深度学习 | `深度学习-批量规范化.pdf` | 《动手学深度学习》 | 批量规范化置于仿射变换与激活函数之间（p1）；Ali Rahimi 2017 NeurIPS 时间检验奖把实践比作炼金术（p7–8） |
| 操作系统 | `os-cpu-scheduling.pdf` | OSTEP 第 7 章（英文） | Round Robin 响应时间好、周转时间差（p6–7） |
| 机器学习数学 | `math-gaussian.pdf` | Mathematics for Machine Learning（英文） | 两个高斯密度的乘积仍是（未归一化的）高斯（p8） |

OCR 提问用 `教材页-提问.png`（OSTEP 第 7 页的真实排版页）。

## 2. 主轮次

每步都给出**期望**，任一期望不成立即记为失败并停下定位，不要跳过继续。

1. **打开首页** `http://127.0.0.1:5173`
   期望：状态栏 `● connected`、`deepseek/deepseek-v4-flash`、`retrieval: hybrid_bge`；侧栏无课程；console 无 error。

2. **新建 4 门课程**：`大语言模型`、`深度学习`、`操作系统`、`机器学习数学`
   点「＋ 新建课程」会弹 `window.prompt`，先挂 dialog 处理器再点击。
   期望：每门课程出现在左栏且带稳定色点；创建后自动切进该课程工作区。

3. **上传教材**：进「知识仓库」，按 1.3 的表把 5 份切片分别上传到对应课程
   hidden `<input type=file>`，不要直接点按钮（会开原生选择器）；用 filechooser/ref 上传。
   期望：上传后自动起索引 job，流水线依次亮起「解析 → 切块 → 向量 → 索引」；结束后状态标签为「已索引」，
   副标题显示 `N 块 · 语义 + 词面检索就绪`。

4. **检索验证**：在「大语言模型」知识仓库检索 `QLoRA`，在「操作系统」检索 `turnaround`
   期望：结果卡片给出资料名 + `p.X` + 排序分；页码与 1.3 的锚点页对得上。

5. **刷新页面**
   期望：4 门课程、5 份资料、索引状态全部还在（服务端持久化，不是前端内存）。

6. **课程会话问锚点事实**：进「大语言模型」课程会话，问
   *"QLoRA 相比 LoRA 多做了什么来省显存？"*
   期望：先出现工具 chip「检索教材 · 命中 N 段」（`origin=seed` 的系统种子检索）；回答里出现 **4-bit 量化**；
   底部 `SOURCES` 列出 `llm-微调-LoRA.pdf:4`~`:6` 之一。

7. **点引用**
   期望：右侧抽屉打开，显示页码与教材原文片段，不是空占位。

8. **跨文档引用编号**：同一会话继续问
   *"Super-NaturalInstructions 这个指令集有多大、什么语言、怎么构建的？"*
   期望：回答给出 **500 万 / 多语言 / 手动构建**；引用指向 `llm-指令数据集.pdf`，编号在本轮内连续且不与上一轮混淆。

9. **一轮内多个引用**：进「深度学习」会话，问
   *"批量规范化层应该放在网络的哪个位置？为什么说内部协变量偏移的解释有争议？"*
   期望：回答同时覆盖「仿射变换与激活函数之间」和 Ali Rahimi 的炼金术类比；`SOURCES` 至少 2 条，页码落在 p1 与 p7–8。

10. **跨语言检索**：进「操作系统」会话，用中文问
    *"时间片轮转为什么响应时间好、周转时间反而差？"*
    再进「机器学习数学」会话问 *"两个高斯密度乘起来还是高斯分布吗？"*
    期望：中文问题命中英文教材，引用分别落在 `os-cpu-scheduling.pdf:6~7`、`math-gaussian.pdf:8`。

11. **课程隔离 + 教材外兜底**：留在「操作系统」会话，问 *"QLoRA 是怎么省显存的？"*
    期望：引用里**不出现**任何 `llm-*.pdf`；回答先说明本课程资料没有，再另起一段以
    「以下不是当前教材结论：」开头给通用知识；不拒答、也不把通用知识伪装成教材结论。

12. **模型自主多轮工具**：进「大语言模型」会话，问
    *"这门课有哪些资料？其中关于指令数据集的部分讲了什么？"*
    期望：除种子检索外还出现 `origin=model` 的工具 chip（资料清单 / 再次检索）；回答同时给出文件清单和内容摘要。
    验证：

    ```bash
    tail -n 3 data/e2e/traces/*.jsonl | .venv/bin/python -c "import sys,json;[print(r.get('status'), 'rounds=%s' % r.get('tool_rounds'), [(t['origin'],t['name'],t['ok']) for t in r.get('tools',[])]) for l in sys.stdin if l.strip().startswith('{') for r in [json.loads(l)]]"
    ```

    期望：最后一条 `status=completed`、`tool_rounds ≥ 1`，`tools` 里既有 `seed` 也有 `model`。

13. **计划 / 档案工具与骨架页**：同一会话问 *"我这门课的学习计划和学习记录是什么？"*
    期望：出现「学习计划 · 暂无计划」「学习档案 · 档案为空」chip，回答如实说没有，不编造计划；
    再看侧栏 `03 学习计划` / `04 学习档案`，分别显示「还没有学习计划」和「还没有证据事件」。

14. **图片提问**：在「操作系统」会话点「图片」上传 `教材页-提问.png`，正文写 *"这页在讲哪几种调度算法？"*
    期望：发送前 attach chip 显示 OCR 转录（英文页，能看到 SJF / Round Robin 字样）；回答基于转录内容作答并带引用。
    这一步会产生一次真实 Qwen-OCR 调用。

15. **通用模式解析**：切回「通用模式」新建会话，问 *"大语言模型这门课里，QLoRA 是怎么省显存的？"*
    期望：顶部出现「本轮解析到：大语言模型」，左栏该会话色点变成课程色，引用来自 `llm-*.pdf`。
    紧接着问 *"帮我复习一下"*
    期望：顶部「本轮未解析到课程」，回答是固定澄清话术「我还不能确定要使用哪门课程的资料……」，
    且**没有任何检索工具 chip**（未解析不取证）。

16. **Wiki 默认关闭**：进任一课程「知识仓库 → Wiki 知识页」
    期望：默认显示「Wiki 尚未启用」；打开开关后才列出已索引资料；点「解析到 Wiki」才出现 job。
    关闭 Wiki 不影响 RAG 检索（回到 RAG 页确认资料仍可检索）。

17. **收尾检查**
    - `read_console_messages`：整轮无 error。
    - 上面的 trace 命令：每一轮都有记录，没有 `status=failed` 的意外条目。
    - 「管理与设置 → 检查服务」：`provider/model` 真实、`retrieval: 语义 + 词面混合`、数据库 migration 版本正常。

## 3. 补充轮次：供应商失败降级（可选，约 2 分钟）

停掉实例，用坏 Key 重启，再问一次第 6 步的问题：

```bash
TEXT_API_KEY=sk-invalid STORAGE_DATA_DIR=data/e2e ./scripts/dev.sh
```

期望：出现 `provider_fallback` 后由本地 responder 完成回答，回答带明确的本地标识，会话仍正常持久化；
状态栏与 health 如实显示降级，不伪装成远端结果。

## 4. 这条测试不覆盖

`session_busy` 并发抢同一会话、`client_request_id` 幂等重放、`stream_interrupted`（需要在流中途切断供应商）、
100 MiB 上限校验、飞书渠道。这些留给后端测试与手工验证。
